# Agent Summary — personal blog (temp-portfolio)

Purpose
- Minimal static personal blog where articles are plain HTML files. Articles live in `writings/` and are linked from `index.html`.

Repository layout (top-level)
- `index.html` — homepage listing articles and linking to `writings/*.html`.
- `styles.css`, `notes.css` — global styles.
- `images/` — media assets, favicons.
- `typefaces/` — preloaded webfonts.
- `writings/` — article HTML files. Some articles include an article-scoped stylesheet (e.g., `article-animation.css`).

Article conventions and patterns
- Each article is a standalone HTML file inside `writings/`.
- Typical head/body pattern:
  - Head links to `../styles.css`, preloads fonts, and may include an article stylesheet (e.g., `article-animation.css`).
  - Body contains a header linking back to `../index.html`, a `<main>` with `article > h1` for the title (using a class like `article-people`, `article-code`, or `article-data` for styling), and a `<time datetime="YYYY-MM-DD">` for the publish date.
- Filenames typically include a slug and year (e.g., `this-website-is-less-than-100kbs-2025.html`).
- Image and favicon paths are relative (e.g., `../images/...` from `writings/`).
- Article category classes on `<h1>`: use `article-people`, `article-code`, or `article-data` to style the heading background color.

Authoring workflow (how you currently write articles)
1. Duplicate an existing article HTML file inside `writings/`.
2. Update the `<h1>` text to the new title and add the appropriate class (`article-people`, `article-code`, or `article-data`).
3. Update the `<time datetime="..."></time>` element with the publish date.
4. Rename the file to the desired slug (keep relative paths intact).
5. Add a link to the new file from `index.html` inside the "Writings" section.
6. Add any images to `images/` and reference them with relative paths from the article.

Testing articles — validate asset and stylesheet links
 - Purpose: ensure each article's `href` and `src` attributes point to existing assets (e.g. `../styles.css`, `../images/...`, or article-scoped styles like `article-animation.css`). This detects broken image, stylesheet, and local-asset links inside `writings/*.html`.

PowerShell (Windows) — quick check

```powershell
# from repo root
$missing = @()
ForEach ($file in Get-ChildItem writings -Filter '*.html') {
  $content = Get-Content $file.FullName -Raw
  $matches = [regex]::Matches($content, '(?:href|src)="([^"]+)"')
  ForEach ($m in $matches) {
    $asset = $m.Groups[1].Value
    if ($asset -match '^https?:') { continue } # skip absolute URLs
    $checkPath = Join-Path $file.DirectoryName $asset
    if (-not (Test-Path $checkPath)) { $missing += "$($file.Name): $asset" }
  }
}
if ($missing.Count -gt 0) { Write-Host "Missing article assets:"; $missing } else { Write-Host "All article asset links valid." }
```

Node (cross-platform) — small script

```node
// save as tools/validate-article-assets.js and run `node tools/validate-article-assets.js`
const fs = require('fs');
const path = require('path');
const writingsDir = path.join(process.cwd(), 'writings');
const files = fs.readdirSync(writingsDir).filter(f => f.endsWith('.html'));
const missing = [];
for (const file of files) {
  const content = fs.readFileSync(path.join(writingsDir, file), 'utf8');
  const attrRegex = /(?:href|src)="([^"]+)"/g;
  let m;
  while ((m = attrRegex.exec(content)) !== null) {
    const asset = m[1];
    if (/^https?:/.test(asset)) continue; // skip external URLs
    let assetPath;
    if (asset.startsWith('..')) assetPath = path.resolve(writingsDir, asset);
    else assetPath = path.resolve(writingsDir, path.dirname(file), asset);
    if (!fs.existsSync(assetPath)) missing.push(`${file}: ${asset}`);
  }
}
console.log(missing.length ? 'Missing article assets:' : 'All article asset links valid', missing);
```

 - Run the PowerShell snippet from the repo root on Windows, or create and run the Node script. These checks skip absolute `http(s)` URLs and focus on local files referenced by the article HTML files.
